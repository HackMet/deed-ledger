- What was done:
  - **Download.** Two steps on every call, as Meta's media docs describe (checked Oct 30, URL in the file): `GET
    https://graph.facebook.com/<version>/<id>?phone_number_id=<id>` with the token → JSON `url`, `mime_type`,
    `file_size`; then an authorized GET on `url`. A retry never reuses a URL (they last 5 minutes). 15 s timeout per
    request; 16 MiB cap checked against `file_size`, `Content-Length` and the streamed bytes. Only an https URL is
    followed (the token goes with it). Errors carry a code (`lookup_http_401`, `download_http_404`, `too_large`,
    `download_timeout`…), never the URL or response text. No token: returns null, so the job retries and then sends
    "No pude descargar…", the existing behavior.
  - **Decoding.** The spike's code, plus: a file that ends inside a page or a packet is refused (the spike kept the
    complete pages), inputs over 16 MiB are refused before parsing, output is 16 kHz mono 16-bit WAV, audio over 10
    minutes is refused from the packet headers before any decoding.
  - **Wasm.** `scripts/extract-opus-wasm.mjs` writes libopus from `opus-decoder` to `dist/opus-decoder.wasm`
    (gitignored, 93,685 bytes, sha256 `8b67eda2…058b4b`), rewriting only when the bytes change so `wrangler dev`
    doesn't loop. Wrangler runs it as `build.command` (dev, deploy); `vitest.config.ts` runs it before tests. The
    `@eshaz/web-worker` stub is aliased in both places, because the test pool doesn't apply wrangler's `alias`.
  - **Transcriber.** `POST https://api.meta.ai/v1/asr/transcribe`, multipart `request` (JSON: `PUSH_TO_TALK`,
    `muse-voice-transcribe-1.0`, `WAV`, `languageBias: ["Spanish"]`) and `audio` (WAV), Bearer `MODEL_API_KEY`, 90 s
    timeout. Rechecked against https://dev.meta.ai/docs/speech-to-text on Oct 30. One attempt; the spike's inner retry
    was dropped so the job's retry is the only one. Refuses `*-contributor` IDs; a blank key fails without a call.
  - **transcribeVoiceNote(deps, tenant, assetId).** Stored asset → `MediaStore.read` → decode → transcribe. Throws
    `VoiceNoteError` (`media_not_stored`, `media_missing`, `no_speech`) or the adapters' errors. Called from a job
    handler, a failure takes the job's normal retries and ends with `couldNotProcess("audio")`: "Perdón, no pude
    escuchar tu nota de voz. ¿Me la mandás otra vez?" (tested). An empty transcript counts as a failure. Logs carry
    the asset and store IDs only.
  - **CPU, 60 s note.** The spike's Node bench (`spikes/audio-decode/bench/node-bench.mjs`, pointed at the moved
    `src` code bundled with esbuild, same `.wasm` bytes), synthetic flite speech + pink noise, mono 48 kHz Opus 24 kbps,
    8 runs, Node 22.15.0, i7-8650U:

    | Audio | OGG | WAV | First run, main-thread CPU | Warm median, main-thread CPU | Warm max, process CPU |
    |---|---|---|---|---|---|
    | 5 s | 15,419 B | 160,044 B | 73 ms | 34 ms | 90 ms |
    | 60 s | 181,821 B | 1,920,044 B | 269 ms | 276 ms | 314 ms |
    | 300 s | 908,569 B | 9,600,044 B | 1.33 s | 1.22 s | 1.31 s |

    In line with the spike (60 s: 229 ms Node, 273–310 ms workerd). ffprobe on the 60 s output: `pcm_s16le`, 16000 Hz,
    1 channel, 16 bits, 60.000000 s. Not measured in workerd or on Cloudflare (the issue asks for the deployed number).
- New dependency: `opus-decoder` 0.7.12 (MIT; embeds libopus, BSD-3-Clause; pulls `@wasm-audio-decoders/common`
  and `@eshaz/web-worker`, both MIT). Why: Muse Voice Transcribe takes only WAV and WhatsApp sends OGG/Opus; an Opus
  decoder is tens of thousands of lines of C, not a few lines of code, and the platform has none. Chosen in A1 over
  LGPL and larger alternatives. Pinned exactly: the injected-module and alias workarounds depend on its internals.

- Not done, risks, open questions:
  - Never run against a real webhook or the real transcriber. Whether the media URL needs anything beyond the
    Authorization header is unknown; the docs show only that header.
  - Meta's `sha256` isn't checked (its encoding isn't documented on the page); R2 hashes what it stores.
  - The lease is 60 s and a transcription may take 90 s (see `docs/architecture.md`, risks). #17 has to extend the
    lease around the call or the lease must grow.
  - Every failure gets 3 attempts, including ones that can't change (a note over 10 minutes, a broken file). Cheap
    (decoding stops before any work), but the owner waits through the retries. A distinct reply for "too long" would
    need a change in the processor.
  - Queue batches of 10: ten 10-minute notes in one batch is about 25 s of CPU against the 30 s default. The spike
    suggested `max_batch_size: 1` for voice; not changed.
  - libopus's BSD notice should ship with the Wasm (open since A1).
  - CPU on Cloudflare's hardware: measure after the first deploy.
